## 1. Sample code for Z-Image-Turbo on the RTX 5090
**Q:** I downloaded the models and disk space is low, so start with Z-Image-Turbo. I want sample code: a quick
test, a class component, and a network API for other users. How long will it take?

**A:** The code is in `zimage_service/`:
| File | Purpose |
|---|---|
| `quick_test.py` | load the model, generate one image, print timing and VRAM |
| `zimage_engine.py` | `ZImageEngine` class: load once, thread-safe `generate()`, batch 1–4, seeds |
| `server.py` | FastAPI: sync `POST /v1/images/generate`, async `POST /v1/jobs` + `GET /v1/jobs/{id}`, API keys, bounded queue, per-key limit, auto-cleanup |
| `client.py` | `ZImageClient` for users |
| `benchmark.py` | 5 warm-up + 100 runs, p50/p95/p99, images/min, peak VRAM → JSON |
| `check_env.py` | checks GPU, torch build, packages and model files before loading |

Key facts:
- Model card settings: `num_inference_steps=9` (= 8 DiT passes), `guidance_scale=0.0` (required for Turbo), BF16.
- The transformer weights on disk are **FP32 (23 GB)** and get cast to BF16 on load. The model folder is 30.6 GB.
- Run **one server process per GPU**. Each process loads its own copy of the model.

Time estimate: environment + first image 30–60 min · API working for others < ½ day · baseline benchmark
1–2 h · full production items from the todo (Redis, S3, monitoring, load tests, H200 worker) about 1–2 weeks.

## 2. Offline packages for the 5090 and H200
**Q:** The 5090 has no internet. torch, transformers and CUDA are already installed there. Collect the
extra wheels in `pkgs/` per machine, also for the H200, compatible with Python 3.10 and 3.12. Put a guide for each step in `cmds/`.

**A:** Yes:
- `cmds/scripts/download_wheels.py` (internet PC) → `pkgs/5090/py3XX`, `pkgs/h200/py3XX`
- `cmds/scripts/install_offline.py` (GPU machine) → `pip install --no-index` from those folders
- Guides `cmds/01`–`10`

**Q:** The 5090 is Windows, the H200 is Ubuntu.
**A:** 5090 → `win_amd64` wheels; H200 → `manylinux` x86_64 wheels (glibc 2.28, which works on Ubuntu 20.04/22.04/24.04).

**Q:** Can we skip step 01 (inventory of the GPU machines) and assume torch, transformers and CUDA are installed?
**A:** Yes, that's the default now ("blind mode").
- Torch and CUDA are **never** downloaded.
- Install into a venv created with `--system-site-packages`. It reuses the installed torch, and new packages go only into the venv. Deleting `.venv` undoes everything.
- transformers wheels are shipped as a fallback. pip keeps the installed transformers if it's compatible and uses the shipped one only if needed.

## 4. Will it run on the 5090 without errors?
**Q:** If I move the project to the offline 5090, can I test the model with no error?

**A:** Likely, but not guaranteed. Everything testable without the GPU passed. Remaining unknowns on the 5090:
| Risk | Detect | Fix |
|---|---|---|
| Installed torch too old for the RTX 5090 (needs a CUDA 12.8+ build, torch ≥ 2.7, driver ≥ 570) | `check_env.py`: `FAIL torch build supports sm_120` | offline torch cu128 wheels (~3 GB), see guide 10 |
| System RAM ≤ 32 GB (model-card loading reads 23 GB FP32 into RAM) | slow load / freeze / OOM | `set ZIMAGE_LOW_CPU_MEM=1` |
| Python other than 3.10–3.13 | `install_offline.py` "folder not found" | build that version |

Quick pre-check on the 5090:
```bat
nvidia-smi
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.get_arch_list())"
systeminfo | findstr /C:"Total Physical Memory"
```

**Q:** Add wheel folders for Python 3.11 and 3.13 (not torch).
**A:** Done. All 8 folders: `pkgs/{5090,h200}/py310, py311, py312, py313` (5090: 213 MB, H200: 253 MB).
- pip applies dependency rules (`python_version`, `sys_platform`) for the **download** machine, not the target.
  `download_wheels.py` now re-checks every wheel's dependencies for the target and fetches anything missing.
- Validation: the 3.10 folders rebuilt this way from Python 3.12 were **identical** to the ones built with a real Python 3.10.
